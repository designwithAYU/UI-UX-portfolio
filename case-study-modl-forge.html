01 — Overview

What MODL Forge does

MODL Forge helps people generate, upload, clean, analyze and prepare datasets for machine-learning model training — without needing to write code at any step.

02 — Problem

ML workflows are easy to get lost in

Complex AI/ML workflows can be difficult for non-technical users to understand and navigate. The design goal was to simplify the workflow into a clear, step-by-step product experience — understandable for beginners, still fast for technical users.

03 — User Flow

One path from raw data to a downloadable model

Dataset Source→ Generate / Upload→ Clean Data→ Quality Analysis→ Review→ Train Model→ Compare Results→ Download Model
04 — Wireframes

Structuring the pipeline before styling it

I kept the wireframes deliberately plain — the goal was to test whether a first-time user could tell where they were in a six-step process just from the layout, before any visual design was applied.

05 — Design Exploration

Finding the right amount of dashboard

Early explorations tried to surface every metric on one screen. It read as noisy and technical — not what a beginner needs to see first. I moved most metrics behind a "Quality Analysis" step and kept the dashboard itself to status and next action.

07 — Design Decisions

A few choices worth explaining

01

A persistent step indicator on every screen

No matter how technical the step, the user always knows where they are in the six-step pipeline and what's next.

02

Status labels instead of raw logs

Replaced technical processing logs with plain labels — "Queued," "Processing," "Ready" — so non-technical users aren't stuck reading console output.

03

One primary action per screen

Every step has a single obvious next action, even on screens with several secondary options.

04

Empty states that explain what to do

Before a dataset is uploaded or a model is trained, the screen tells the user exactly what to do next instead of showing a blank panel.
